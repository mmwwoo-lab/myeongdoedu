# 개인정보·안전 검토 보고서

작성일: 2026년 11월 25일 (한국 시간)  
담당: 개인정보·안전 검토 담당자  
대상: 사진·카메라를 이용한 관상 문화 체험 웹앱

## 업무지시서

비서실장 지시에 따라 실명 없이 이용할 수 있는 입력 흐름, 브라우저 내 사진 처리, 삭제 및 카메라 종료 동작을 검토한다. 얼굴에서 개인의 성격·능력·운명·건강 또는 민감한 속성을 추론하는 기능은 제공하지 않는다. 법률 준수 인증이나 보안 보증이 아니라, 구현된 처리 방식과 검증 범위를 보고한다.

인수 기준:

1. 별명·나이·성별 입력창을 제공하되 모두 선택 입력으로 운영한다. 나이와 성별은 얼굴의 형태 분류나 설명을 바꾸는 근거로 사용하지 않는다.
2. 선택한 사진과 카메라 영상은 브라우저 메모리에서만 처리한다. 사진·입력 정보·랜드마크·결과를 서버로 전송하지 않는다.
3. 앱에서 localStorage, sessionStorage, IndexedDB, 쿠키 또는 분석 추적 도구로 개인 정보를 저장하지 않는다.
4. 카메라는 명시적인 시작 동작과 브라우저 권한 허용 후에만 켠다. 촬영·취소·중지·페이지 종료에서 모든 영상 트랙을 종료한다.
5. 사진 교체 및 전체 삭제 시 기존 Object URL을 해제한다. 전체 삭제는 입력 정보와 결과를 함께 초기화한다.
6. 원본 사진이나 EXIF 정보를 파일·로그로 보관하지 않는다. 결과 다운로드는 사용자가 요청할 때만 생성하고 포함 정보를 명확히 알린다.
7. 처리 실패를 성공처럼 표시하지 않는다. 얼굴 검출 실패·지원하지 않는 환경·여러 얼굴 검출 등의 한계를 설명하고 재촬영이나 직접 선택 경로를 제공한다.
8. 결과는 보이는 형태의 단순 그림 및 전통 도상의 문화적 이야기로 한정한다. 실제 개인에 대한 재물·직업·관계·수명·질병 등의 판단은 제공하지 않는다.

## 설계상 개인정보 처리 흐름

사용자 동작 → 브라우저에서 파일 읽기 또는 카메라 영상 표시 → 메모리에서 형태 확인 → 단순 그림과 문화 설명 표시 → 전체 삭제 또는 탭 종료.

앱 자산과 얼굴 검출 모델을 내려받는 네트워크 요청은 사진 업로드와 구분해야 한다. 호스팅 사업자가 처리하는 접속 IP·요청 로그까지 “어떤 정보도 수집하지 않는다”라고 표현해서는 안 된다. 사진의 브라우저 내 처리 여부와 운영 인프라의 일반 접속 기록은 별도의 사항이다.

## 소스 검토 결과

검토 대상은 `dist/index.html`, `dist/app.mjs`, `dist/face-core.mjs` 및 동일 출처로 번들된 MediaPipe 자산이다. 직접 작성된 앱 코드에서 다음 사항을 확인했다.

| 검토 항목 | 확인 결과 |
| --- | --- |
| 입력 최소화 | 실명란이 없고 별명·나이·성별 모두 선택 입력이다. 성별은 ‘응답 안 함’이 기본값이다. |
| 나이·성별 활용 | 형태 측정 함수와 결과 생성 함수에 나이·성별을 전달하지 않는다. |
| 사진 처리 | `createImageBitmap`으로 읽고 canvas에 다시 그려 최대 변 1,600px JPEG로 생성한다. 앱은 원본 파일·EXIF를 별도 보관하지 않는다. |
| 파일 제한 | JPG·PNG·WebP, 15MB 이하, 해상도 4천만 화소 이하로 제한한다. |
| 분석 경로 | MediaPipe 모듈·WASM·모델을 동일 사이트의 `vendor` 경로에서 불러오며 브라우저의 IMAGE 모드로 실행한다. |
| 외부 전송 | 직접 작성된 앱 코드에 사진/폼 값 업로드, fetch, XMLHttpRequest, sendBeacon, WebSocket 호출이 없다. 라이브러리 자산을 불러오는 네트워크 요청은 필요하다. |
| 브라우저 영구 저장 | 직접 작성된 앱 코드에서 localStorage·sessionStorage·IndexedDB·쿠키 저장을 사용하지 않는다. |
| 카메라 시작 | 사용자 버튼으로만 `getUserMedia`를 호출하고 `audio:false`로 요청한다. |
| 카메라 종료 | 촬영·취소·사진 교체·전체 삭제·페이지 숨김·페이지 종료·다른 메뉴 이동에서 트랙을 중지한다. 권한 응답이 늦게 온 경우도 request ID를 검사해 트랙을 중지한다. |
| 사진 해제 | 사진 교체·제거·전체 삭제·페이지 종료에서 Blob Object URL을 해제한다. bitmap도 close 처리한다. |
| 비동기 취소 | epoch 검사로 삭제 후 지연된 사진 로딩/분석 결과가 재표시되는 것을 방지한다. |
| 다중 얼굴 | `numFaces:2`로 검출하고 두 명 이상이면 한 사람 사진을 요청한다. 검출 수 제한이 있으므로 사진 속 인원 수 전체를 세는 기능은 아니다. |
| 분석 실패 고지 | 검출 실패·분석 불가·사진 없는 예시를 구분하고 직접 선택 경로임을 표시한다. |
| 파일 내보내기 | 사용자 클릭 때 SVG/TXT를 생성하고 다운로드용 URL은 1초 후 해제한다. 원본 사진·나이·성별은 포함하지 않는다. TXT에는 별명이 포함되며 화면에 이를 알린다. |
| 결과 내용 | 형태 묘사 및 앱이 창작한 도상 감상문으로 한정한다. 개인의 성격·능력·건강·재물·운명을 판단하지 않는다는 문구가 화면과 TXT에 들어 있다. |

### 통합 개발 담당자에게 전달한 보완 사항

1. 스크립트 실행 실패 시 기본 HTML form submit이 개인정보를 URL에 실어 전송하지 않도록, 코드에서 사용하지 않는 별명·나이·성별의 `name` 속성을 제거할 것을 요청했다.
2. 전체 삭제 시 숨겨진 결과 DOM의 별명·그림·설명까지 비울 것을 요청했다. 단순히 결과 영역을 숨기고 상태 변수를 null로 바꾸는 것만으로는 숨겨진 DOM의 텍스트가 남는다.
3. 취소된 분석과 재분석이 모델 로딩 Promise를 공유할 때 이전 요청이 새 요청의 모델을 먼저 close할 수 있는 경합 가능성을 전달했다. 개인정보 전송 문제는 아니지만 자동 분석의 안정성과 관련 있다.

최종 소스 재검토 결과 세 사항 모두 반영되었다. 별명·나이·성별 입력의 `name` 속성이 제거되어 기본 form 직렬화 대상에서 제외된다. `clearResult()`는 별명이 표시된 제목과 결과 그림·설명 DOM을 비운다. 모델 수명은 별도의 `modelGeneration`으로 관리하여 일반 분석 취소와 전체 삭제를 구분하며, 전체 삭제 전에 시작된 모델 로딩은 완료 후 즉시 폐기한다.

`node --check`로 앱 모듈과 핵심 모듈의 문법 검사도 통과했다. 이 담당자의 최종 판정은 **소스에서 확인 가능한 개인정보 설계 기준 충족**이다. 실제 카메라와 네트워크 계측 검증을 완료했다는 의미는 아니다.

## 사용 안내에 포함할 내용

- 실명 대신 별명을 사용할 수 있으며 나이·성별은 입력하지 않아도 이용할 수 있다.
- 본인 사진 또는 사용 허락을 받은 사진만 사용한다.
- 정면에서 얼굴 하나만 보이는 사진이 가장 적합하며 조명·각도·가림에 따라 형태 확인이 달라진다.
- 전통 관상은 과학적으로 검증된 개인 평가 방법이 아니다. 설명은 문화·오락용이며 중요한 의사결정에 사용하지 않는다.
- 결과 파일을 직접 내려받으면 기기에 보관된다. 앱의 전체 삭제가 이미 다운로드한 파일까지 삭제하지는 않는다.
- 공유 기기에서는 사용 후 전체 삭제를 누르고 탭을 닫는다.

## 검증 범위와 한계

소스 검토는 코드에 구현된 데이터 흐름을 확인하는 절차다. 브라우저·운영체제·확장 프로그램·호스팅 계층의 메모리 처리나 접속 기록까지 보증하지 않는다. 실제 카메라 권한, 기기별 호환성 및 네트워크 전송 여부는 실행 환경에서 별도 확인이 필요하다. 본 보고서는 법률 자문, 개인정보 관련 인증 또는 침투 테스트 결과가 아니다.
